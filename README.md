# Live Translation

Синхронний переклад мовлення в реальному часі для відеодзвінків (Google Meet, Zoom тощо) на macOS.
Ви говорите російською або українською, а співрозмовник чує англійський переклад **вашим власним голосом**.

```
[Ваш мікрофон] → VAD → STT (Whisper) → LLM-переклад (Ollama) → TTS (клон голосу) → [BlackHole 16ch] → Meet
```

Увесь конвеєр працює **локально** на Apple Silicon. Є й хмарна альтернатива через Gemini Live API (див. [нижче](#хмарна-альтернатива-gemini-live-api)).

## Можливості

- **Локальна обробка:** розпізнавання мовлення, переклад і синтез працюють без хмари.
- **Клонування голосу** з короткого запису (10–20 с), без донавчання моделі.
- **Конвеєрна обробка:** поки синтезується фраза N, фраза N+1 уже розпізнається.
- **Кілька TTS-рушіїв:** F5-TTS, XTTSv2 (з клонуванням), Kokoro, macOS `say` (швидкі, без клонування).
- **Маршрутизація звуку** через віртуальні пристрої BlackHole.

## Вимоги

- macOS на Apple Silicon (M1 і новіші)
- Python 3.11
- [Homebrew](https://brew.sh)
- [Ollama](https://ollama.com) (встановлюється скриптом)
- [BlackHole](https://github.com/ExistentialAudio/BlackHole) 2ch / 16ch (встановлюється скриптом)
- ~10 ГБ вільного місця для моделей

## Встановлення

```bash
git clone https://github.com/abalcer/live-translation.git
cd live-translation
./setup_env.sh
source .venv/bin/activate
```

Скрипт `setup_env.sh` встановлює:
- Homebrew (якщо його немає);
- BlackHole 2ch і 16ch;
- Ollama та модель перекладу (за замовчуванням `qwen2.5:7b-instruct`);
- PortAudio, Python 3.11 і віртуальне середовище з залежностями.

Іншу модель перекладу можна вказати так:

```bash
OLLAMA_MODEL=llama3.1:8b-instruct-q4_K_M ./setup_env.sh
```

Модель, яку використовує конвеєр, задається в `config.yaml → translation.model`.
Щоб порівняти швидкість і якість кількох моделей на однаковому наборі фраз (з тим самим промптом, що й у конвеєрі):

```bash
python bench_translate.py qwen2.5:7b-instruct gemma3:12b qwen3:14b
python bench_translate.py -f phrases.txt -n 3 gemma3:12b   # власні фрази, по рядку
```

## Налаштування звуку

1. Перевірте назви аудіопристроїв:
   ```bash
   python3 -c "import sounddevice as sd; print(sd.query_devices())"
   ```
2. Впишіть їх у `config.yaml` → `audio.devices`. Назви залежать від мови системи: на українській macOS мікрофон називається «Мікрофон MacBook Pro».
3. У Google Meet / Zoom виберіть **BlackHole 16ch** як мікрофон.

## Відтворення вашого голосу

Є чотири способи змусити TTS говорити вашим голосом:

| | **1. Клонування з короткого запису** | **2. Донавчання Piper (VITS)** | **3. Донавчання XTTSv2** | **4. Конвертація голосу (RVC)** |
|---|---|---|---|---|
| Стан | ✅ працює зараз | 🗓 заплановано | 🗓 заплановано | ✅ працює зараз |
| Що записати | 10–20 с мовлення | ~60–90 хв: ви читаєте **англійські** речення | ~30–90 хв звичайного мовлення (російською або іншою мовою зі списку XTTSv2) | ~10–30 хв мовлення **будь-якою мовою**, зокрема українською |
| Зразок голосу під час роботи | потрібен, модель копіює голос із нього | не потрібен, голос «вшитий» у модель | обробляється один раз при старті | не потрібен, тембр «вшитий» у модель RVC |
| Швидкість синтезу | ~3–5 с на фразу | **~0.1–0.3 с** на фразу, навіть на CPU | ~2–3 с на фразу | Kokoro + ~0.25–0.8 с на конвертацію фрази (MPS) |
| Схожість голосу | обмежена тим, що вловлюється з кількох секунд | висока й стабільна, інтонація трохи «рівна» | висока, природна інтонація, буває нестабільність | висока схожість тембру; вимова та інтонація — від базового TTS |
| Вимова англійської | від моделі | **ваша**, з вашим акцентом | від моделі, можливий акцент | **носійська** (від базового TTS) |
| Тренування | не потрібне | PC з RTX 5070 Ti, кілька годин | PC з RTX 5070 Ti, кілька годин | PC з RTX 5070 Ti, ~1 год |

**Рекомендація:** для перекладу наживо найважливіша затримка, тому основна ціль — **варіант 2 (Piper)**. Він прибирає найповільніший етап конвеєра.
Найдешевший спосіб перевірити, чи вам подобається «ваш» англійський голос, — **варіант 4**: він потребує найменше записів і не вимагає читати англійською. Ним же можна згенерувати датасет для Piper із носійською вимовою (див. «Синтетичний датасет для Piper» у варіанті 4).

> 💡 **Важливо щодо мови записів.** Ви говорите російською чи українською, а TTS озвучує **англійською**.
> Piper — одномовна модель: щоб вона говорила англійською вашим голосом, датасет треба записувати англійською (з вашим природним акцентом).
> Запис сам по собі акцент не виправляє: Piper вивчить саме ту вимову, яку почує.
> XTTSv2 багатомовна й сама переносить голос між мовами, але **української серед її мов немає**, тому записувати для неї краще російською.
> RVC переносить лише тембр і від мови не залежить, тому для неї підходять записи будь-якою мовою.

### Варіант 1: клонування з короткого запису

Моделі **не потрібно донавчати**. F5-TTS і XTTSv2 клонують голос «на льоту» (zero-shot) з короткого зразка вашого мовлення.

#### 1. Запишіть зразок голосу

Потрібно 10–20 секунд чистого мовлення без фонового шуму:

```bash
ffmpeg -f avfoundation -i ":0" -t 15 -ac 1 -ar 24000 reference/reference_speaker.wav
```

Поради:
- Записуйте в тихій кімнаті, тримайте мікрофон на сталій відстані.
- Говоріть природно, у тому темпі й тоні, яким розмовляєте на дзвінках.
- Обріжте тишу на початку й у кінці. Найкраще працюють 8–15 секунд суцільного мовлення.
- Записуйте мовою, якою говорите найчастіше. Тембр перенесеться й на англійську.

#### 2. Додайте транскрипт (для F5-TTS)

F5-TTS потрібен точний текст запису. Створіть поруч файл `reference/reference_speaker.txt` з дослівним текстом.
Якщо файлу немає, його автоматично згенерує Whisper під час першого запуску.

> ⚠️ Якщо ви перезаписали `.wav`, **видаліть старий `.txt`**. Інакше текст не збігатиметься з аудіо, і якість різко впаде.

#### 3. Увімкніть рушій із клонуванням

У `config.yaml`:

```yaml
routes:
  - name: outgoing_mic_to_meet
    voice_reference: "reference/reference_speaker.wav"
    voice_reference_text: ""        # порожньо = взяти з .txt або розпізнати автоматично

tts:
  engine: "f5_tts"                  # або "xtts_v2"
  speed: 1.0
  nfe_step: 8
```

Рушії `say` і `kokoro` **не клонують голос** і ігнорують запис. Щоб вони говорили вашим тембром, поєднайте їх з RVC (варіант 4).

#### 4. Перевірте результат

```bash
python tts_test.py "Привіт, це перевірка мого голосу."
python tts_test.py --translate "Привіт, як справи?"      # спершу перекласти англійською
python tts_test.py --engine xtts_v2 --nfe-step 16 "Тест"  # порівняти рушії та якість
```

Результат відтворюється й зберігається в `logs/tts_test_<час>.wav`.

#### Що впливає на якість

| Параметр | Вплив |
|---|---|
| Чистота запису | Найважливіший фактор: шум і луна потрапляють у клон |
| `tts.engine` | F5-TTS краще передає тембр, XTTSv2 краще підтримує різні мови |
| `tts.nfe_step` | Більше значення дає чистіший звук, але повільніший синтез (16 ≈ 5 с на фразу на MPS) |
| `tts.speed` | Темп мовлення. Значення 1.0 звучить найприродніше |
| `tts.seed` | Фіксоване значення робить голос стабільнішим між фразами |

### Варіант 2: донавчання Piper на вашому голосі (заплановано)

[Piper](https://github.com/rhasspy/piper) — швидка нейромережева TTS на архітектурі VITS. Беремо готову англійську модель і донавчаємо її на ваших записах. Результат — окрема модель `.onnx`, яка завжди говорить вашим голосом без жодного зразка.

**План:**
1. **Запис датасету.** Скрипт показує англійські речення по одному й записує кожне в окремий WAV (22 050 Гц, mono). Він також формує `metadata.csv` у форматі LJSpeech (`файл|текст`). Мета — 60–90 хвилин чистого мовлення, приблизно 800–1200 речень.
2. **Тренування на PC з RTX 5070 Ti.** Скрипт донавчає англійський чекпойнт Piper (наприклад, `en_US-lessac-medium`) на датасеті й експортує `.onnx`. На Mac (MPS) тренування непрактично повільне. Див. «[Тренування на PC з RTX 5070 Ti](#тренування-на-pc-з-rtx-5070-ti)».
3. **Інтеграція.** Новий рушій `tts.engine: "piper"` у `src/tts_cloner.py` синтезує мову локально з `models/<ваша-модель>.onnx`.

### Варіант 3: донавчання XTTSv2 (заплановано)

Донавчання GPT-частини XTTSv2 на ваших записах. Для цього достатньо звичайного мовлення рідною мовою (наприклад, записів власних дзвінків або монологів), а модель сама переносить голос на англійську. Голос звучить природніше, ніж у Piper, але синтез повільніший. Ознаки голосу (speaker latents) обчислюються один раз при старті й кешуються.

Обмеження: української XTTSv2 не підтримує, тож записи мають бути російською. Довге донавчання лише на одній мові погіршує англійську (з'являється акцент), тому кроків тренування має бути небагато.

### Варіант 4: конвертація голосу RVC

[RVC](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI) (Retrieval-based Voice Conversion) не синтезує мову з тексту, а «перефарбовує» готове аудіо у ваш тембр. Слова, вимову та інтонацію бере з вхідного звуку, а тембр — з вашої моделі. Тому англійську озвучує TTS із носійською вимовою (Kokoro), а RVC робить її вашим голосом.

```
Translate → Kokoro (EN, носійська вимова) → RVC (ваш тембр) → AudioPlayer
```

Етап RVC **опційний**: він вмикається одним параметром і працює з виходом будь-якого рушія TTS. Якщо його вимкнути, конвеєр працює як раніше.

#### 1. Запишіть датасет

10–30 хвилин чистого мовлення будь-якою мовою (WAV, 40 або 48 кГц, mono). Текст не важливий, транскрипт не потрібен. Підійде, наприклад, читання книжки вголос або монологи без чужих голосів.

#### 2. Натренуйте модель на PC з RTX 5070 Ti

RVC v2 у [Applio](https://github.com/IAHispano/Applio), орієнтовно ~1 год (див. «[Тренування на PC з RTX 5070 Ti](#тренування-на-pc-з-rtx-5070-ti)»). Результат — файли `<ім'я>.pth` і `<ім'я>.index`. Скопіюйте обидва на Mac у `models/`.

#### 3. Встановіть Applio на Mac

```bash
./setup_rvc.sh
```

Applio жорстко прописує власні версії `torch`, `numpy` та інших пакетів, тому живе окремо від `.venv` проєкту: у `vendor/applio` (не потрапляє в git) із власним середовищем. Скрипт також завантажує ембедер contentvec і модель висоти тону rmvpe (~600 МБ). `main.py` запускає RVC окремим процесом (`src/rvc_worker.py`) і передає йому аудіо через pipe. Воркер доповнює кожну фразу тишею до цілих секунд: Metal компілює обчислення під кожну нову довжину аудіо, а так довжини повторюються й прогріваються заздалегідь.

#### 4. Увімкніть у `config.yaml`

```yaml
tts:
  engine: "kokoro"
  kokoro:
    voice: "am_michael"             # голос тієї ж статі й висоти, що й ваш
  voice_conversion:
    enabled: true                   # false — вимкнути RVC
    model: "models/my_voice.pth"
    index: "models/my_voice.index"
    pitch: 0                        # зсув тону в півтонах
    index_rate: 0.3                 # 0..1: наскільки підтягувати тембр до датасету
    protect: 0.33                   # 0..0.5: зберігати приголосні й дихання з TTS
```

- `pitch` залишайте 0, якщо висота голосу TTS близька до вашої. Інакше RVC «переспівує» інтонацію, і голос звучить неприродно.
- `index_rate` у тесті найближче до голосу звучало 0.3. Більші значення сильніше тягнуть до тембру з датасету, але можуть змазувати англійські звуки.
- **Повернутися до `say`:** `engine: "say"` і `voice_conversion.enabled: false`.

#### 5. Перевірте

```bash
python tts_test.py "Hi everyone, thanks for joining the call today."
python tts_test.py --no-vc "Same phrase without RVC"          # порівняти з чистим Kokoro
python tts_test.py --translate "Привіт, як справи?"
```

Під час старту RVC прогрівається ~15 с, щоб перша фраза не чекала. Конвертація фрази довжиною 1–12 с займає ~0.25–0.8 с. У лозі `main.py` з'являється окрема колонка `VC` із часом конвертації кожної фрази.

#### Синтетичний датасет для Piper (заплановано)

Kokoro озвучує 800–1200 англійських речень, RVC перетворює їх у ваш тембр. Далі кожну фразу перевіряють: Whisper — чи збігається текст, resemblyzer або ECAPA — чи схожий голос. Невдалі відкидаються. На цьому датасеті виконуються кроки 2–3 варіанту 2. Результат — Piper із вашим тембром, носійською вимовою і найменшою затримкою, і для цього не треба читати англійською самому.

Обмеження: RVC може додавати артефакти на шиплячих, диханні й дуже високих чи низьких нотах. Природність інтонації обмежена базовим TTS. У синтетичному датасеті похибки обох моделей копіюються в Piper, тому фільтрування обов'язкове.

### Тренування на PC з RTX 5070 Ti

Тренування (варіанти 2–4) відбувається на окремому PC з NVIDIA RTX 5070 Ti (16 ГБ VRAM). Конвеєр і синтез працюють на Mac: на PC потрібні лише датасет і скрипти тренування, а готові моделі переносяться на Mac у `models/`.

- **PyTorch із CUDA 12.8 або новішою.** RTX 50xx (архітектура Blackwell, `sm_120`) працює лише з PyTorch 2.7+ у збірках `cu128` і новіших. Старі версії, які часто прописані в залежностях RVC-WebUI, Piper і Coqui, падають з помилкою `no kernel image is available`. Встановлюйте PyTorch окремо, до решти залежностей:
  ```bash
  pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu128
  python -c "import torch; print(torch.cuda.get_device_name(0), torch.cuda.get_arch_list())"  # має бути sm_120
  ```
- **ОС.** Тренування Piper орієнтоване на Linux, тож на Windows використовуйте WSL2 (драйвер NVIDIA ставиться у Windows, CUDA всередині WSL працює сама). Applio має готовий інсталятор і для Windows.
- **Piper.** Оригінальний репозиторій `rhasspy/piper` архівовано, а його код тренування прив'язаний до старого PyTorch. Беріть актуальний форк [`OHF-Voice/piper1-gpl`](https://github.com/OHF-Voice/piper1-gpl).
- **XTTSv2.** Беріть підтримуваний форк [`coqui-tts`](https://github.com/idiap/coqui-ai-TTS), а не архівований `coqui-ai/TTS`.
- **VRAM.** 16 ГБ досить для всіх трьох варіантів. Якщо бракує пам'яті (`CUDA out of memory`), зменште `batch_size`. Найвимогливіше донавчання XTTSv2.
- **Перенесення.** Датасет і моделі — ваші біометричні дані. Переносьте їх напряму (USB, локальна мережа), а не через публічні хмарні диски чи git.

### Поради для запису датасету (варіанти 2–4)

- Одна кімната, той самий мікрофон і відстань до нього в усіх сесіях. Без луни, фонової музики й шуму вентилятора.
- Записуйте сесіями по 15–20 хвилин, щоб голос не втомлювався і не змінювався.
- Читайте природно, у темпі дзвінка, без «дикторської» інтонації.
- Перепишіть фразу, якщо в ній є помилка, кашель або сторонній звук: одна погана фраза шкодить більше, ніж допомагає десять добрих.
- Датасет — це ваші біометричні дані: зберігайте його поза репозиторієм (папки `reference/` і `models/` вже в `.gitignore`).

## Запуск

```bash
source .venv/bin/activate
python main.py
```

Зупинка: `Ctrl+C`. Під час старту голосовий зразок «прогрівається», тому перша фраза не чекатиме на завантаження.

### Маршрути

У `config.yaml` → `routes` описано напрямки перекладу. Параметр `speak: false` вимикає озвучення: переклад лише друкується в консолі (зручно для налагодження).

## Хмарна альтернатива: Gemini Live API

`gemini_translate.py` — окремий скрипт, у якому один двонапрямлений потік до Google Gemini Live робить усе: розпізнавання, переклад і озвучення. Затримка нижча, ніж у локального конвеєра, але потрібен платний API-ключ, а голос не клонується.

```
[Мікрофон] ──16 кГц PCM──▶ Gemini Live ──24 кГц PCM──▶ ресемплінг ──▶ [BlackHole 2ch] → Meet
```

### Запуск

```bash
cp .env.example .env     # впишіть GEMINI_API_KEY (https://aistudio.google.com/apikey)
python gemini_translate.py
```

У Google Meet виберіть **BlackHole 2ch** як мікрофон. Зупинка: `Ctrl+C`.
У консолі видно розпізнаний текст (`почуто`), переклад і події VAD.

```bash
python gemini_translate.py --list-devices              # перелік аудіопристроїв
python gemini_translate.py --target de                 # перекладати німецькою
python gemini_translate.py --input-device "MacBook"    # вибрати мікрофон за назвою
python gemini_translate.py --model <назва-моделі>      # інша модель Gemini Live
```

### Налаштування: `config.yaml` → `gemini:`

Прапорці командного рядка мають пріоритет над конфігом.

| Ключ | Призначення |
|---|---|
| `model` | Модель Live API, за замовчуванням `gemini-3.5-live-translate-preview` |
| `input_device` | Підрядок назви мікрофона; `""` означає системний мікрофон за замовчуванням |
| `output_device` | Куди відтворювати переклад (`BlackHole 2ch`) |
| `chunk_size` | Розмір аудіобуфера в семплах |
| `target_language_code` | Мова перекладу: `en`, `de`, `es`, `uk`… |
| `echo_target_language` | `true` — повторювати й мовлення, яке вже звучить цільовою мовою |
| `show_transcripts` | Друкувати транскрипти й події сесії |

Відповідь Gemini приходить із частотою 24 кГц і перетворюється на частоту вихідного пристрою. Без цього звук у Meet зникає або відтворюється з неправильною швидкістю.

> ⚠️ Live API працює лише на платному рівні. Якщо на балансі немає кредитів, сесія одразу обривається з помилкою `1011 — prepayment credits are depleted` (керування: <https://ai.studio/projects>).

```
├── main.py               # локальний конвеєр перекладу

├── tts_test.py           # тестування синтезу / клонування голосу
├── bench_translate.py    # порівняння моделей перекладу (затримка та якість)
├── config.yaml           # усі налаштування
├── setup_env.sh          # встановлення залежностей
├── setup_rvc.sh          # встановлення Applio для RVC (опційно)
├── CLAUDE.md             # інструкції для Claude Code
├── src/
│   ├── audio_stream.py   # захоплення й відтворення звуку
│   ├── vad_processor.py  # виявлення мовлення (Silero VAD)
│   ├── stt_transcriber.py# розпізнавання (mlx-whisper)
│   ├── translator.py     # переклад (Ollama)
│   ├── tts_cloner.py     # синтез і клонування голосу
│   ├── voice_converter.py# RVC: ваш тембр поверх TTS (опційно)
│   ├── rvc_worker.py     # процес RVC у середовищі Applio
│   ├── rvc_protocol.py   # обмін аудіо між конвеєром і процесом RVC
│   └── utils.py
├── reference/            # ваш зразок голосу (не потрапляє в git)
├── models/               # кеш моделей і ваша модель RVC (не потрапляє в git)
├── vendor/applio/        # Applio для RVC (не потрапляє в git)
└── logs/                 # логи та тестові WAV
```

## Конфіденційність

Файли в `reference/` (ваш зразок голосу), `.env` (API-ключі) та `logs/` додано в `.gitignore`, тому вони **не публікуються** в репозиторії.
Не викладайте свій зразок голосу у відкритий доступ: з ним будь-хто може синтезувати мовлення вашим голосом.
